Alur Sistem

Flow Lengkap
Dari Login ke Fitur

Bagaimana sistem bekerja dari inisiasi pertama hingga penggunaan fitur-fitur utama.

🚀 Inisiasi & Login

1

App Bootstrap & Database Load

App.jsx memanggil /api/data/public untuk load snapshot database. Data publik (jadwal, kalender, silabus) di-cache ke localStorage sebagai offline fallback. Branding sekolah (warna, logo, nama) langsung diterapkan ke dokumen.

Fetch /api/data/public LocalStorage Cache Offline Fallback Dynamic Branding
2

Halaman Login dengan Rate Limiting

Form login di Login.jsx mengirim POST ke /api/auth/login. Server menerapkan rate limiting per-username dan per-IP (max 10 percobaan). Token JWT dikembalikan dan disimpan di sessionStorage. CAPTCHA tersedia untuk reset password.

Rate Limiting CAPTCHA Verif JWT Token Session Storage
3

Role-based Dashboard Routing

Setelah login berhasil, AdminApp.jsx mendeteksi role pengguna (admin, waka, guru, kepsek, dll) dan merender sidebar serta konten yang sesuai. Setiap tab di sidebar dirender oleh AdminContentRouter.jsx.

Role Detection Dynamic Sidebar Feature Flags

📅 Alur Penjadwalan

4

Input Master Data (Guru, Kelas, Mapel, Ruangan)

Admin/Waka Kurikulum mengisi data master melalui tab terpisah. Tersedia bulk import via CSV atau Excel. Data tersinkron ke PostgreSQL melalui saveDatabaseNow() dan disinkronkan ke auth snapshot untuk login guru.

Bulk Import CSV PostgreSQL Sync Auth Snapshot Sync
5

Konfigurasi Beban & Ketersediaan

Waka Kurikulum mengatur beban mengajar guru per mapel per kelas/jurusan (termasuk bulk multi-kelas), dan ketersediaan jam mengajar per hari. Aturan lanjutan (advanced rules) untuk distribusi mata pelajaran juga dapat dikonfigurasi.

Beban Mengajar Availability Matrix Advanced Rules
6

Generate Jadwal Otomatis

Sistem mengevaluasi kesiapan data (readiness check), kemudian menjalankan algoritma penjadwalan yang mempertimbangkan beban guru, ketersediaan, kapasitas ruangan, aturan blok JP, dan konflik. Hasil dapat diedit manual, dipreview, dan diekspor.

Readiness Check Constraint Algorithm Manual Edit Export Excel/PDF

🎒 Alur PKL Siswa

7

Pendaftaran & Penugasan PKL

Admin/Hubin menginput data perusahaan mitra, mendaftarkan siswa ke program PKL secara manual, dan menugaskan guru pembimbing. Data siswa dari mst_students tidak otomatis terdaftar — harus manual untuk kontrol kualitas.

Manual Register Penugasan Guru Data Perusahaan
8

Monitoring Harian Siswa PKL

Siswa login ke portal /student, mengisi logbook harian, absensi berbasis GPS (verifikasi koordinat ke radius lokasi perusahaan). Guru pembimbing dapat memvalidasi jurnal dan mencatat kunjungan lapangan dari portal /pkl-teacher.

GPS Absensi Logbook Digital Validasi Guru Kunjungan Lapangan

👆 Alur Absensi Hikvision

9

Sinkronisasi Perangkat Fingerprint

Admin mengonfigurasi perangkat Hikvision melalui modul hikvision.mjs. Data absensi ditarik secara otomatis via node-cron (scheduled job). Enkripsi password perangkat menggunakan AES untuk keamanan.

Hikvision API AES Encryption Cron Job Auto-fetch
10

Rekap & Laporan Kehadiran

Data mentah dari mesin absensi diolah menjadi rekap harian, mingguan, dan bulanan per individu. Tersedia laporan terpisah untuk guru, karyawan, dan siswa. Export langsung ke Excel yang siap cetak/distribusi.

Rekap Harian Per Individu Export Excel Print-ready

Audit Sistem

Keamanan, Performa
& Temuan Bug

Hasil audit menyeluruh terhadap keamanan, performa, dan potensi bug pada sistem.

🔐 Keamanan (Security)
✓ OK

JWT Token Auth + Rate Limiting

Setiap request ke API dilindungi JWT. Rate limiting aktif per-username dan per-IP (max 10 percobaan login). CAPTCHA tersedia untuk fitur lupa password.

✓ OK

Password Hashing bcrypt

Semua password disimpan dalam bentuk bcrypt hash. Verifikasi menggunakan timing-safe comparison. Password plaintext tidak pernah disimpan.

✓ OK

Enkripsi Password Perangkat Hikvision

Password mesin fingerprint dienkripsi dengan AES sebelum disimpan ke database. Dekripsi hanya dilakukan server-side saat request ke perangkat.

✓ OK

CORS Policy Diatur Ketat

Konfigurasi CORS di cors.mjs mengizinkan origin yang terdaftar saja. Tidak ada wildcard CORS terbuka.

✓ OK

Password Strip dari Payload Publik

Saat load data publik di App.jsx, field password admin dan guru di-strip sebelum disimpan ke localStorage (tidak ada password hash di client-side storage).

⚠ WARN

Password Default Lemah (123456 / 123)

Guru dan karyawan baru dibuat dengan password default 123 (3 karakter). Meski bisa login dengan hash lama, sangat disarankan menambahkan mekanisme "force change password" untuk pengguna baru.

⚠ WARN

LocalStorage Menyimpan Snapshot DB (tanpa enkripsi)

Data publik (tanpa password) di-cache ke localStorage untuk offline mode. Jika perangkat diakses pihak lain, data sekolah seperti jadwal dan profil bisa dibaca. Perlu enkripsi atau TTL expiry.

⚠ WARN

Token JWT Tidak Ada Revokasi (Blacklist)

Token JWT valid sampai expire. Tidak ada mekanisme logout aktif yang menginvalidasi token di server. Logout hanya menghapus token dari client. Perlu implementasi token blacklist atau refresh token pattern.

⚡ Performa (Performance)
✓ OK

Code Splitting & Lazy Loading

Seluruh halaman dimuat via React.lazy() + Suspense. Bundle dibagi per kategori: react, charts, icons, xlsx, pdf, maps melalui manualChunks di Vite config. Mengurangi initial bundle secara signifikan.

✓ OK

Virtual Scroll untuk Tabel Besar

Menggunakan @tanstack/react-virtual untuk rendering tabel dengan data besar (siswa, jadwal, dll). Hanya baris yang terlihat di viewport yang di-render.

✓ OK

Offline Fallback dari LocalStorage

Jika server tidak dapat dijangkau, data terakhir dari localStorage digunakan untuk tetap menampilkan konten (bukan halaman error kosong).

⚠ WARN

AdminApp.jsx Terlalu Besar (160KB, ~3716 Baris)

File utama AdminApp.jsx sangat besar dan berisi terlalu banyak state, logic, dan komponen. Ini menyebabkan re-render tidak efisien dan menyulitkan maintenance. Perlu dipecah ke custom hooks dan komponen terpisah.

⚠ WARN

DashboardPage.jsx Terlalu Besar (99KB)

File dashboard juga sangat besar. Komponen stat cards, shortcuts, dan chart sebaiknya dipecah ke file terpisah untuk performa React reconciliation.

ℹ INFO

Tidak Ada Server-Side Pagination di Beberapa Endpoint

Beberapa endpoint mengembalikan seluruh data sekaligus. Untuk sekolah dengan data besar, perlu implementasi pagination server-side untuk endpoint seperti daftar siswa dan rekap absensi.

🐛 Bug & Potensi Masalah
✓ FIXED

[DIPERBAIKI] Password Minimum 8 Karakter Memblokir Login Default

Validasi minimum 8 karakter mencegah login dengan password lama 123456 (6 karakter). Sudah diperbaiki — minimum diturunkan ke 6 karakter di frontend dan backend.

✓ FIXED

[DIPERBAIKI] Layout Mobile Jurnal Harian Guru Berantakan

Filter dropdown dan statistik tidak responsif di mobile. Sudah diperbaiki — grid dan filter menyesuaikan ukuran layar.

⚠ WARN

Auto-sync PKL Dihapus Tapi Comment Tidak Jelas

Dalam auth-server.mjs terdapat komentar bahwa auto-sync siswa ke PKL dihapus karena menyebabkan semua siswa terhitung sebagai peserta PKL. Perlu dokumentasi yang lebih jelas untuk tim developer.

⚠ WARN

Scratch Files di Folder src/

Terdapat 3 file scratch (scratch_find_teachers_state.mjs, scratch_search_adminapp_useeffect.mjs, scratch_search_loading_adminapp.mjs) di dalam src/ yang seharusnya tidak ada di production.

⚠ WARN

ESLint: Banyak Warning react-hooks/exhaustive-deps

File besar seperti AdminApp.jsx dan AdminSidebar.jsx menggunakan eslint-disable global untuk menekan error. Ini menyembunyikan potensi bug seperti stale closure dan missing dependency di useEffect.

ℹ INFO

Scroll Position Sidebar Memakai sessionStorage Langsung

Di AdminSidebar.jsx posisi scroll disimpan langsung ke sessionStorage. Lebih baik menggunakan state management (Zustand) untuk konsistensi.

ℹ INFO

Sidebar Fetch API di useEffect Tanpa AbortController

Fetch jadwal piket di AdminSidebar.jsx tidak menggunakan AbortController. Jika komponen unmount sebelum response, akan terjadi memory leak / state update on unmounted component.

✅ Fitur & Completeness
✓ OK

Error Boundary Global

App dibungkus ErrorBoundary.jsx sehingga crash komponen tidak merusak seluruh aplikasi. Pengguna melihat UI fallback yang informatif.

✓ OK

Feature Flags Terpusat

Fitur dapat diaktifkan/nonaktifkan melalui featureSettings di database tanpa perlu deployment ulang. Admin dapat toggle fitur melalui UI manajemen fitur.

✓ OK

Cloud Backup ke AWS S3

Data database dapat dibackup ke AWS S3. Mendukung restore dari backup cloud tanpa ketergantungan penuh pada storage lokal.

ℹ INFO

Beberapa Modul Masih Placeholder

Beberapa file seperti BKDashboard.jsx (1.2KB), MasterPoin.jsx (341B), LaporanAbsensi.jsx, ManajemenPiket.jsx masih sangat minimal — belum memiliki implementasi penuh.

ℹ INFO

Tidak Ada Unit / Integration Tests

Script npm run test ada di package.json namun tidak ditemukan file test yang terimplementasi. Perlu coverage test terutama untuk logika generate jadwal dan auth.
